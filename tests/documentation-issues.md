# 项目文档问题清单

> 检查范围：`README.md`、`docs/01` 至 `docs/10`
>
> 检查结论：现有测试和 Markdown lint 未发现明显文件级错误；以下问题主要涉及内容准确性、术语、覆盖完整性、平台边界和可维护性。

## 一、P0 / 高优先级

### 1. “软换行”概念表述不准确

**位置：** `docs/02-text-format.md`，2.1 节。

当前将“在段落间添加一个空行”称为软换行。空行在 Markdown 中通常表示新段落，应区分：

- 软换行：普通换行，具体显示取决于渲染规则。
- 硬换行：行尾两个空格或反斜杠。
- 新段落：两段之间保留一个空行。

**建议：** 修改术语和示例，明确空行表示新段落，而不是普通换行。

### 2. 两个空格换行示例不够直观

**位置：** `docs/02-text-format.md`，约第 21-34 行。

示例将说明文字写在行尾两个空格之后，读者不容易看出真正的换行标记。

**建议：** 使用“行尾存在两个空格”的单独说明，或使用 `··` 表示示例中的两个空格，并明确实际使用时应替换为空格。

### 3. “插入动态图片”标题不准确

**位置：** `docs/05-images.md`，5.2 节。

Mermaid、GeoJSON、TopoJSON 和 ASCII STL 本质上是图表或可视化代码块，不是动态图片。

**建议：** 改为“GitHub 图表与可视化代码块”或“插入图表和可视化内容”。

### 4. 支持层级仍需在各节明确区分

**位置：** 全文，尤其是 `docs/02-text-format.md`、`docs/05-images.md`、`docs/08-github-features.md`。

文档涉及 CommonMark、正式 GFM、GitHub 平台能力、第三方编辑器扩展、HTML 和完整 LaTeX。虽然 README、第 9 章和第 10 章有总体说明，但具体章节中仍容易让读者把它们混为一谈。

**建议：** 每个功能小节增加支持层级标识，例如：

```text
支持层级：CommonMark / GFM / GitHub 平台 / 第三方扩展
```

## 二、P1 / 中优先级：内容遗漏

### 5. 缺少 HTML 注释语法

建议新增：

```markdown
<!-- 这是注释，不会显示在页面正文中 -->
```

需要说明：注释源码仍然可见，不要写入密钥、Token 或敏感信息。

### 6. GitHub 标题锚点规则不够完整

**位置：** `docs/01-headings.md`、`docs/04-links.md`。

建议补充：

- 英文字母通常转为小写。
- 空格通常变为 `-`。
- 多数标点会被移除。
- 中文通常保留。
- 重复标题通常会追加 `-1`、`-2` 等后缀。
- 修改标题可能导致原有链接失效。

### 7. 缺少定义列表说明

定义列表不是 CommonMark 或正式 GFM 语法，但部分编辑器支持：

```markdown
术语
: 定义内容
```

建议放入“第三方扩展”章节，并明确 GitHub 不应依赖此语法。

### 8. 缺少 `<kbd>` 快捷键标签

GitHub README 中常见：

```markdown
按 <kbd>Ctrl</kbd> + <kbd>C</kbd> 复制
```

应说明这是 HTML 标签用法，不是 Markdown 或 GFM 原生语法。

### 9. 删除线缺少 `<s>` 语义差异

当前介绍了 GFM 的 `~~文本~~` 和 HTML 的 `<del>`，可补充 `<s>`：

- `<del>` 表示内容被删除。
- `<s>` 表示内容不再准确或不再适用。
- GFM 文档优先使用 `~~文本~~`。

### 10. 图片路径和尺寸限制说明不足

**位置：** `docs/04-links.md`、`docs/05-images.md`。

建议补充：

- `./file.md`、`../README.md` 和 `/README.md` 的路径差异。
- GitHub/Linux 对文件名大小写敏感，Windows 本地环境可能不敏感。
- `width` 和 `height` 通常可用于 `<img>`，但 `style` 不可靠。
- 外部图片可能因防盗链、网络策略或服务失效而无法显示。

## 三、P1 / 中优先级：示例和平台兼容性

### 11. `==高亮==` 的表述存在冲突

**位置：** `docs/02-text-format.md`，2.8 节。

文档前面说明该语法不是 CommonMark/GFM，后面又称“主流平台通用”，容易造成误解。

**建议：** 改为：

> `==文本==` 是部分 Markdown 编辑器支持的扩展语法，不属于 CommonMark 或 GFM，GitHub 中通常不会渲染为高亮。

### 12. 颜色 HTML 示例容易被复制到 GitHub

**位置：** `docs/02-text-format.md`，2.12 和 2.13 节。

`<span style="color:red">`、`<div style="background:red">` 和 `<font>` 等示例虽然附带了限制说明，但展示较多，仍可能让读者误以为 GitHub 支持自定义颜色。

**建议：** 在示例开头明确标注“仅适用于独立 HTML”，并优先给出 GitHub 中的替代方案。

### 13. Mermaid 时序图示例存在潜在语法错误

**位置：** `docs/05-images.md`，5.2.2 节，约第 138、140 行。

示例使用：

```mermaid
z-xl: 文本
```

该写法不像标准 Mermaid 时序图消息语法，可能无法正常渲染。

**建议：** 在 GitHub 页面实际预览，并改成标准箭头，例如 `z->>l: 文本` 或 `z-->>l: 文本`。

### 14. 数学公式支持范围需要更谨慎

**位置：** `docs/07-math.md`。

建议进一步说明：

- GitHub 数学公式不是完整 LaTeX 环境。
- `align`、`equation` 等环境不能简单等同于完整 LaTeX 编译结果。
- `\text{}`、中文和复杂宏可能存在渲染差异。
- 普通美元符号需要转义，避免和公式分隔符冲突。

## 四、P2 / 低优先级：章节定位和表达

### 15. 徽章章节偏离 Markdown 语法主题

**位置：** `docs/08-github-features.md`，8.3 节。

徽章本质上是第三方服务生成的图片，再通过 Markdown 图片或链接语法嵌入，不是 GFM 特有语法。

**建议：** 保留基本原理和示例，将详细的 shields.io 参数移入附录或改为外部链接。

### 16. 第三方服务依赖较多

涉及：

- shields.io
- contrib.rocks
- star-history.com
- 社交平台徽章服务

这些服务可能变更接口、访问较慢或失效。

**建议：** 统一增加第三方服务提示；长期稳定展示的关键图片建议导出并保存到仓库。

### 17. 章节命名不完全一致

README 中称“五、图片与图表”，但 `docs/05-images.md` 标题为“五、图片”，内部又使用“插入动态图片”。

**建议：** 统一标题，例如：

```markdown
# 五、图片与图表
## 5.2 GitHub 图表与可视化代码块
```

### 18. 部分文字过于口语化

例如 `docs/08-github-features.md` 中的“这个网页每次都打开奇慢。。”。

**建议：** 改为“如果访问较慢，也可以查看本仓库整理的 Emoji 参考”。

### 19. 中英文排版不统一

建议统一以下写法：

- `Emoji 表情`
- `HTML 字符引用`
- `Git 仓库`
- `GitHub 仓库`
- `shields.io`

## 五、P2 / 可维护性问题

### 20. README 手写目录维护成本高

**位置：** `README.md`。

目录包含大量三级标题链接，标题修改后容易出现锚点失效或目录不同步。

**建议：** 使用工具自动生成目录，或只保留一级、二级目录。

### 21. 外链检查不能完全保证第三方资源稳定

项目已有本地链接检查和 external-links workflow，但动态徽章、图片和数据服务仍可能临时不可用。

**建议：** 对关键内容使用仓库内静态资源，第三方服务只作为示例。

### 22. “显示效果如下”使用块引用可能改变解析语境

多个章节把示例效果放在 `>` 块引用中。对于列表、表格、代码块、Alerts、脚注和数学公式，块引用可能改变实际解析结果。

**建议：** 容易受上下文影响的示例尽量直接展示；或者明确说明块引用仅为排版用途，实际使用时不需要添加 `>`。

## 六、建议新增主题

| 建议主题 | 优先级 | 说明 |
|---|---:|---|
| HTML 注释 `<!-- -->` | 高 | README 维护中常见，需提醒敏感信息风险 |
| GitHub 标题锚点完整规则 | 高 | 与目录和页内跳转直接相关 |
| 原始 HTML 允许/过滤示例 | 高 | 容易出现跨平台误用 |
| `<kbd>` 快捷键标签 | 中 | README 中常见 |
| 定义列表 | 中 | 第三方扩展，需明确 GitHub 不支持 |
| Emoji 短代码与 Unicode 的区别 | 中 | 支持范围和跨平台效果不同 |
| 图片路径和大小写敏感问题 | 中 | Windows、Linux、GitHub 行为可能不同 |
| Mermaid 支持边界 | 中 | GitHub 支持的图表和版本可能变化 |
| 美元符号与数学公式冲突 | 中 | 数学文档中常见问题 |
| 文件名、空格和 URL 编码 | 中 | 链接和图片路径容易出错 |

## 优先修复顺序

1. 修正“软换行”和“动态图片”等术语。
2. 检查并修复 Mermaid 时序图示例。
3. 在各章节明确 CommonMark、GFM、GitHub 和第三方扩展的归属。
4. 补充 HTML 注释、GitHub 锚点规则和原始 HTML 过滤边界。
5. 统一章节标题、中文排版和第三方服务说明。
6. 再考虑压缩 README 目录并增加更多扩展主题。
