## 待处理问题

### P2 低优先级：章节定位和表达

### 15. 徽章章节偏离 Markdown 语法主题

**位置：** `docs/08-github-features.md`，8.3 节。

徽章本质上是第三方服务生成的图片，再通过 Markdown 图片或链接语法嵌入，不是 GFM 特有语法。

**建议：** 保留基本原理和示例，将详细的 shields.io 参数移入附录或改为外部链接。

### 16. 第三方服务依赖较多

涉及：

- shields.io
- contrib.rocks
- star-history.com
- 社交平台徽章服务

这些服务可能变更接口、访问较慢或失效。

**建议：** 统一增加第三方服务提示；长期稳定展示的关键图片建议导出并保存到仓库。

### 17. 章节命名不完全一致

README 中称"五、图片与图表"，但 `docs/05-images.md` 标题为"五、图片"，内部又使用"插入动态图片"。

**建议：** 统一标题，例如：

```markdown
# 五、图片与图表
## 5.2 GitHub 图表与可视化代码块
```

### 18. 部分文字过于口语化

例如 `docs/08-github-features.md` 中的"这个网页每次都打开奇慢。。"。

**建议：** 改为"如果访问较慢，也可以查看本仓库整理的 Emoji 参考"。

### 19. 中英文排版不统一

建议统一以下写法：

- `Emoji 表情`
- `HTML 字符引用`
- `Git 仓库`
- `GitHub 仓库`
- `shields.io`

## P2 可维护性问题

### 20. README 手写目录维护成本高

**位置：** `README.md`。

目录包含大量三级标题链接，标题修改后容易出现锚点失效或目录不同步。

**建议：** 使用工具自动生成目录，或只保留一级、二级目录。

### 21. 外链检查不能完全保证第三方资源稳定

项目已有本地链接检查和 external-links workflow，但动态徽章、图片和数据服务仍可能临时不可用。

**建议：** 对关键内容使用仓库内静态资源，第三方服务只作为示例。

### 22. "显示效果如下"使用块引用可能改变解析语境

多个章节把示例效果放在 `>` 块引用中。对于列表、表格、代码块、Alerts、脚注和数学公式，块引用可能改变实际解析结果。

**建议：** 容易受上下文影响的示例尽量直接展示；或者明确说明块引用仅为排版用途，实际使用时不需要添加 `>`。
