## 3.1 无序列表

### 3.1.1 Markdown语法实现方式

无序列表使用星号(`*`)、加号(`+`)或是减号(`-`)作为列表标记，这些标记后面要添加一个空格，然后再填写内容

<br/>

案例：

```markdown
+ 无序列表，使用加号

* 无序列表，使用星号

- 无序列表，使用减号
```

<br/>

显示效果如下：

> + 无序列表，使用加号
>
> * 无序列表，使用星号
>
> - 无序列表，使用减号

<br/>

### 3.1.2 HTML标签实现方式

HTML使用 `<ul>` 标签包裹列表，`<li>` 标签包裹列表项，嵌套直接多层 `<ul>` 标签。

案例：

```markdown
<ul>
  <li>活塞效应（核心风源）</li>
  <li>空调通风系统（背景风）
    <ul>
      <li>新风输入</li>
      <li>废风排出</li>
    </ul>
  </li>
</ul>
```

显示效果如下：

> <ul>
>   <li>活塞效应（核心风源）</li>
>   <li>空调通风系统（背景风）
>     <ul>
>       <li>新风输入</li>
>       <li>废风排出</li>
>     </ul>
>   </li>
> </ul>

<br/>

### 3.1.3 LaTeX实现方式

LaTeX使用`itemize`环境创建无序列表。

```latex
\begin{itemize}
  \item 第一项
  \item 第二项
  \begin{itemize}
    \item 嵌套项目
  \end{itemize}
\end{itemize}
```

该语法用于完整LaTeX文档，GitHub数学公式中不能创建正文列表环境。

<br/>

## 3.2 有序列表

### 3.2.1 Markdown语法实现方式

有序列表使用数字并加上 `.` 或 `)` 来表示。

注意：Markdown 会自动修正数字顺序, 但会以第一个数字开始。

案例：

```markdown
2. 有序列表（实际显示为2）

3. 有序列表（修正，实际显示为3）

6. 有序列表（修正，实际显示为4）
```

显示效果如下：

> 2. 有序列表
>
> 3. 有序列表
>
> 4. 有序列表

<br/>

#### 列表嵌套

无序列表，有序列表，任务列表，这3者是支持嵌套使用的。

<br/>

案例：

```markdown
+ 无序列表，使用加号
  1. 有序列表
    - [x] 已完成的任务
```

<br/>

显示效果如下：

> + 无序列表，使用加号
>   1. 有序列表
>     - [x] 已完成的任务

<br/>

#### 列表解析规则

列表标记后至少要有一个空格。无序列表可以使用 `-`、`+` 或 `*`；有序列表使用数字加 `.` 或 `)`。在同一个有序列表中，首项数字决定列表的起始编号，后续项目的数字通常会被自动递增。

案例：

```markdown
3) 第一项
1) 第二项
1) 第三项
```

显示效果如下：

> 3) 第一项
> 1) 第二项
> 1) 第三项

列表项之间没有空行时，通常会解析为紧凑列表；列表项之间有空行，或某个列表项内部包含空行时，会解析为松散列表。松散列表中的每个列表项通常会被包裹为独立段落。

列表项可以包含多个段落。后续段落需要缩进到列表项内容的位置；使用两个空格并不适用于所有列表标记，使用与列表内容对齐的缩进更可靠。

列表项中也可以嵌套块引用、围栏代码块等块级内容。嵌套内容通常需要缩进到列表项内容的位置：

````markdown
- 第一段内容

  第二段内容，仍属于第一项。

  > 这是第一项中的块引用。

  ```text
  这是第一项中的代码块。
  ```

- 第二项
````

显示效果如下：

> - 第一段内容
>
>   第二段内容，仍属于第一项。
>
>   > 这是第一项中的块引用。
>
>   ```text
>   这是第一项中的代码块。
>   ```
>
> - 第二项

有序列表只使用第一项的数字作为起始编号，后续项目中的数字不会决定最终编号：

```markdown
3. 第一项
1. 第二项
1. 第三项
```

显示效果如下：

> 3. 第一项
> 4. 第二项
> 5. 第三项

列表标记后的空格数量和后续内容的缩进会影响列表项边界。推荐使用一个空格开始列表内容，并让多行内容与第一行文字对齐；不要依赖混合制表符和空格来控制嵌套层级。

```markdown
- 推荐写法
  续行内容

- 嵌套列表
  - 子项目
```

显示效果如下：

> - 推荐写法 续行内容
>
> - 嵌套列表
>   - 子项目

在列表项中使用代码块时，围栏代码块比缩进代码块更容易保持层级清晰，也可以直接指定语言标识符。

<br/>

### 3.2.2 HTML标签实现方式

HTML使用 `<ol>` 标签包裹有序列表，使用 `<ul>` 标签包裹无序列表，使用 `<li>` 标签包裹每个列表项；列表嵌套时，直接在 `<li>` 中使用多层 `<ol>` 或 `<ul>` 标签。

案例：

```markdown
<ol>
  <li>活塞效应（核心风源）</li>
  <li>空调通风系统（背景风）
    <ul>
      <li>新风输入</li>
      <li>废风排出</li>
    </ul>
  </li>
</ol>
```

显示效果如下：

> <ol>
>   <li>活塞效应（核心风源）</li>
>   <li>空调通风系统（背景风）
>     <ul>
>       <li>新风输入</li>
>       <li>废风排出</li>
>     </ul>
>   </li>
> </ol>

<br/>

### 3.2.3 LaTeX实现方式

LaTeX使用`enumerate`环境创建有序列表。

```latex
\begin{enumerate}
  \item 第一步
  \item 第二步
  \begin{enumerate}
    \item 子步骤
  \end{enumerate}
\end{enumerate}
```

列表编号会由LaTeX自动维护，也可以配合`enumitem`宏包进行更复杂的编号配置。

<br/>

## 3.3 任务列表

### 3.3.1 Markdown语法实现方式

任务列表（又称复选框列表）是正式GFM扩展语法，常用于待办事项、项目计划等场景。

在无序列表项前加上方括号即可创建任务列表：
+ 方括号内为 小写字母`x`​ 或 大写字母`X`：表示任务已完成（已选中）
+ 方括号内为 空格：表示任务未完成（未选中）

<br/>

案例：

```markdown
- [ ] 未完成的任务
- [x] 已完成的任务
  - [X] 二级已完成的任务
- [ ] 另一个未完成的任务
```

<br/>

显示效果如下：

> - [ ] 未完成的任务
> - [x] 已完成的任务
>   - [X] 二级已完成的任务
> - [ ] 另一个未完成的任务

<br/>

注意： 方括号 `- [ ]` 与文本之间必须有一个空格，否则无法正确渲染

```markdown
# 正确用法
- [ ] 未完成的任务

# 错误用法
- [ ]未完成的任务
```

显示效果如下：

> 正确用法
> - [ ] 未完成的任务
>
> 错误用法
> - [ ]未完成的任务

<br/>

### 3.3.2 HTML标签实现方式

语法： `<input type="checkbox">` + 文本，`checked` 属性标记已勾选

案例:

```markdown
<ul>
  <li><input type="checkbox"> 分析活塞效应成因</li>
  <li><input type="checkbox" checked> 整理空调通风系统原理</li>
</ul>
```

显示效果如下：

> <ul>
>   <li><input type="checkbox"> 分析活塞效应成因</li>
>   <li><input type="checkbox" checked> 整理空调通风系统原理</li>
> </ul>

注意：独立HTML页面可以使用交互式`<input>`，但GitHub会对Markdown中的表单控件进行限制，不能把它当作可提交的HTML表单使用。

### 3.3.3 LaTeX实现方式

LaTeX没有内置的交互式任务列表，可以在`itemize`中使用数学符号模拟复选框。下面的例子需要`amssymb`宏包。

```latex
\usepackage{amssymb}

\begin{itemize}
  \item[$\square$] 未完成的任务
  \item[$\boxtimes$] 已完成的任务
\end{itemize}
```

生成的PDF中这些符号通常不可交互，只用于视觉展示。

<br/>
